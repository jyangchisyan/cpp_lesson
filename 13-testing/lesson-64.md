# 第 64 課：設計邊界值測試

[返回本類索引](README.md)

## 這課要學什麼

第 62 課學會寫 `assert`，第 63 課學會看編譯警告。接下來要決定：**應該測哪些數字？** 測試不只要有「一般正確值」，更要檢查規則剛好改變的位置。

## 5 分鐘重點

### 1. 找到規則的界線

學生專題只接受 `0` 到 `100` 分，兩端都包含在內。這個範圍有兩條界線：`0` 與 `100`。對每條界線，至少測「界線本身」與「跨過界線的下一個整數」：

| 測試分數 | 預期有效？ | 為什麼 |
| --- | --- | --- |
| `-1` | 否 | 剛好低於下限 |
| `0` | 是 | 下限也算有效 |
| `100` | 是 | 上限也算有效 |
| `101` | 否 | 剛好高於上限 |

`50` 這種中間值也可以測，但它通常無法發現把 `<= 100` 誤寫成 `< 100` 的錯誤。`100` 與 `101` 才能區分這兩種寫法。這種挑選「界線兩側」輸入的方法叫做**邊界值測試**。

### 2. 把預期結果寫成斷言

建立一個 `bool isValidScore(int score)`：分數在 `0` 到 `100` 時回傳 `true`，否則回傳 `false`。可以用 `&&` 表示「同時符合下限與上限」。

```cpp
assert(!isValidScore(-1));
assert(isValidScore(0));
assert(isValidScore(100));
assert(!isValidScore(101));
```

每個 `assert` 都對應表格中的一列。若其中一項失敗，先看**是哪個分數**，再檢查比較符號與等號。測試程式與 [學生專題](../12-student-project/student_average.cpp) 分開寫，這一課不需要修改專題原始碼。

## 一道練習

在本資料夾建立 `score_range_test.cpp`：加入 `<cassert>`、`<iostream>`，寫出 `isValidScore`，再照表格寫四個斷言。四項都通過後印出「邊界測試通過」。從專案根目錄編譯執行：

```sh
cd 13-testing
g++ -std=c++17 -Wall -Wextra score_range_test.cpp -o score_range_test
./score_range_test
```

最後暫時讓 `100` 被判成無效，重新執行，確認 `100` 那項斷言會失敗；觀察完再恢復正確判斷。若編譯器說找不到 `isValidScore`，檢查函式是否定義在 `main()` 之前。
