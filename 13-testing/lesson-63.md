# 第 63 課：閱讀編譯警告

[返回本類索引](README.md)

## 這課要學什麼

第 62 課用 `assert` 檢查執行結果；這一課學會在**執行之前**看編譯器的提醒。程式能編譯，不代表邏輯一定正確。

## 5 分鐘重點

### 1. 警告與錯誤不同

**錯誤（error）**通常表示無法完成編譯；**警告（warning）**表示編譯器發現可疑寫法，可能仍會產生執行檔。警告不是「可以直接忽略」：本課的程式可以執行，結果卻與原本意圖相反。

編譯時加入 `-Wall -Wextra`，可以開啟許多常用的警告。它們不代表「所有可能的警告」都會出現，但很適合日常練習：

```sh
g++ -std=c++17 -Wall -Wextra warning_practice.cpp -o warning_practice
```

### 2. 先看一段故意有問題的程式

```cpp
#include <iostream>

int main() {
    int score = 60;
    int unused = 5;

    if (score = 100) {
        std::cout << "滿分\n";
    } else {
        std::cout << "未滿分\n";
    }
}
```

`unused` 被宣告後從未使用，會產生「未使用變數」的警告。更重要的是，`score = 100` 是**指定值**，不是比較；它會把 `score` 改成 `100`，整個條件因而成立，程式錯誤地印出「滿分」。比較是否相等要使用 `==`。編譯器通常也會對把指定運算放進 `if` 條件提出警告。

### 3. 怎麼讀訊息

警告常包含 `檔名:行號:欄號`、`warning` 與原因。先找到你寫的檔案和行號，再讀原因；編譯器後面列出的標準函式庫細節不一定是問題根源。一次修正一處，重新編譯，確認警告消失，最後**實際執行**確認輸出。沒有警告也不保證程式完全正確，所以第 62 課的測試仍然重要。

## 一道練習

在本資料夾自行建立 `warning_practice.cpp`，輸入上面的程式，並從專案根目錄執行：

```sh
cd 13-testing
g++ -std=c++17 -Wall -Wextra warning_practice.cpp -o warning_practice
./warning_practice
```

先記下編譯器指出的兩種問題，以及程式為何錯印「滿分」。接著移除未使用變數，並把指定值改為比較；重新編譯後應沒有這兩項警告，執行結果應為「未滿分」。不同編譯器的警告措辭可能不同，重點是理解行號與原因。
